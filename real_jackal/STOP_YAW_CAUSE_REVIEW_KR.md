# 반복 정지와 회전: 확인한 원인과 아직 확인할 부분

이 문서는 `jackal-real-drive-fixes-20260912`의 `c15c6f8`을 기준으로 한 코드 검토와
`jackal-stability-20260916`의 수정 내용을 설명한다. 과거 영상의 모든 정지를 하나의
원인으로 확정한 보고서는 아니다. 실제 주행 성능은 연구실에서 비교해야 한다.

## 0.5m 경계 때문에 멈추는가?

**그 조건으로 멈출 수 있다. 하지만 모든 정지가 그 때문인 것은 아니다.**
설정에 서로 다른 거리 조건이 있으며 기준점과 역할도 다르다.

| 설정 | 기본값 | 의미와 동작 |
| --- | --- | --- |
| `robot_radius + static_safety_margin` | 0.34 + 0.16 = **0.50m** | 경로상의 로봇 중심 주위 검사 반경. 점유 셀 또는 미관측 영역과 겹치면 후보 경로 탈락 |
| `obstacle_stop_distance` | **0.75m** | 전방 ±0.70rad(약 ±40°) 범위의 최소 LaserScan 거리. 기준 미만이면 추종기가 선속도·각속도 모두 0으로 정지 |
| `obstacle_slow_distance` | **1.40m** | 위 전방 거리 기준으로 0.75~1.40m 구간에서 감속 |
| Nav2 `inflation_radius` | **0.55m** | 전역 경로용 costmap의 장애물 주변 비용 확장 범위. 그 경계를 밟았다고 직접 정지 명령을 내리는 값은 아님 |
| `goal_tolerance` | **0.50m** | 최종 목적지 도달 판단 거리. 장애물 여유와 별개 |
| `minimum_human_center_distance` | **1.20m** | 예측 경로와 보행자 예상 위치 사이 최소 중심 거리 검사 |
| `human_stop_distance` | **0.90m** | 현재 인식된 보행자가 가까우면 추종기에서 즉시 정지 |

여기서 0.50m는 **로봇 외곽에서 추가로 0.50m를 띄운다는 뜻이 아니다.**
로봇 반경 0.34m와 여유 0.16m를 합한 중심 기준 값이다. 검사는 0.10m 셀의
로컬 맵에서 수행하므로, 물리 공간의 정확한 원 경계와 완전히 일치하지는 않는다.
미관측 셀도 막힌 곳으로 취급한다. 이번 변경에서 이 정책과 반경은 유지했다.

경로 하나가 탈락해도 다른 유효 후보가 있으면 주행할 수 있다. **현재 후보 전부가
탈락할 때** bridge가 hold를 보내며 tracker가 정지한다. 이전 경로를 검사 없이
유지하거나 장애물을 통과하는 경로를 실행하도록 변경하지 않았다.

사용자가 제공한 9월 15일 오프라인 분석에서는 고정 맵·고정 후보 145개에 대해
반경 0.50→0.45m 변경 시 충돌 후보가 22→21개였다. 이 결과는 5cm 여유 축소가
주된 해결책이라는 가설을 지지하지 않는다. 그 수치를 이번 영상의 정지 횟수로
해석할 수는 없다. 0.40m 비교 결과도 물리 안전을 입증한 결과가 아니다.

## 코드에서 재현한 회전·정지 메커니즘

### 1. 작은 위치 잡음으로 모델 좌표 방향이 급변

기존 `heading_from_history`는 마지막 두 위치의 차이가 1mm를 넘으면 그 벡터의
각도를 모델 기준 방향으로 사용한다. 차체 yaw가 0°여도 횡방향 차이가
0.9mm→1.1mm가 되면 입력 heading이 0°→90°로 바뀌는 사례를 재현했다.

수정 기본값 `motion_guarded`는 정지·저속·신뢰할 수 없는 이동에서는 odometry yaw를
사용하고, 충분하고 일관된 이동 이력이 있으면 학습과 같은 마지막 이동 벡터 방향을
사용한다. 실제 사용 방향과 원래 함수의 방향을 함께 기록한다. 모델 재학습은 하지 않았다.

이 재현은 **함수의 민감도에 대한 증거**다. 과거 특정 회전에 실제로 어떤 theta가
사용됐는지는 해당 주행의 입력 이력이 있어야 확정할 수 있다.

### 2. 추종점이 뒤쪽 점으로 선택되는 문제

기존 꼭짓점 기준 선택은 동일 직선 경로에서 로봇 위치가 조금 바뀌었을 때 추종점이
뒤로 이동할 수 있었다. 합성 사례에서 목표 방향이 약 −149°→−4.1°로 바뀌었다.
경로 선분에 현재 위치를 투영한 뒤 경로를 따라 전방 거리만큼 이동해 추종점을 선택하도록
수정했고, 같은 사례에서 두 위치 모두 약 −4.1°를 유지한다.

또 짧은 예측 경로의 끝점을 이미 지나친 경우 그 끝점을 뒤로 쫓아 180° 방향 전환을
요청할 수 있었다. 수정본은 경로를 소진한 상태를 `path_exhausted`로 기록하고 다음
유효 경로를 기다린다. 이것은 최종 목적지 도달과 다른 상태다.

### 3. 안전한 후보 사이에서도 좌우 경로가 바뀜

기존 선택에는 이전 경로와의 연속성이 포함되지 않았다. 수정본은 **현재 안전 검사를
통과한 후보들만** 대상으로 현재 방향, 전방 구간의 회전, 이전 경로와의 차이,
중간 목표와의 거리를 비교한다. 후보 점수는 로그에 남는다. 더 안전한 경로가 없다는
문제를 점수 조정만으로 해결할 수는 없다.

### 4. 좁은 복도에서 회전이 전방 정지를 유발할 수 있음

전방 정지 검사는 예측 경로의 0.50m 검사와 독립적이다. 예를 들어 이상적인 폭 1.20m
직선 복도의 중앙에서 벽까지 0.60m일 때, 전방 ±0.70rad 범위의 벽 측정 거리는
대략 `0.60 / sin(0.70) = 0.93m`이다. 현재 설정에서는 이미 감속 구간이다.
차체가 벽 쪽으로 20° 틀어지면 `0.60 / sin(0.70 + 20°) = 0.69m`가 되어
0.75m 정지 조건에 걸릴 수 있다. 로봇 중심에서 벽까지는 여전히 0.60m다.

이는 설정의 동작을 설명하는 **가정한 복도 기하 예시**이며 영상 속 복도 폭을 측정한
결과가 아니다. 회전 문제를 먼저 개선하고 실제 전방 최소 거리·각도와 정지 사유를
기록해야 한다. 이번에 0.75m를 줄이거나 근접 정지 중 회전을 허용하지 않았다.

### 5. 추론 중 센서 콜백 대기와 계산 지연

기존 동기 추론 구조에서는 모델이 계산하는 동안 같은 ROS 실행 스레드의 센서 콜백과
이력 표본 처리가 대기한다. 특히 수정 도중 추가한 계산 후 신선도 검사와 조합하면
0.60초를 넘는 추론이 새 센서를 처리하지 못한 채 반복 탈락하는 회귀가 있었다.
이 회귀는 배포 전에 재현하고 수정했다. **과거 영상의 원인으로 소급해 단정하지 않는다.**

수정본은 하나의 추론 worker에 복사한 지도·입력을 전달하고 센서 수신을 계속한다.
완료 후 현재 지도·로봇 위치·보행자로 후보를 다시 검사하며, 목표·좌표계가 바뀌었거나
1.20초를 넘긴 결과는 사용하지 않는다. 이는 센서 timeout을 늘리는 변경이 아니다.
실제 GPU 추론과 지도 검사에 걸리는 시간은 연구실에서 기록해야 한다.

## 영상에서 확인한 범위

제공된 `IMG_5669.mov`는 약 34.5초의 실제 복도 주행 영상이다. 이동 촬영으로 로봇과
카메라의 상대 위치가 함께 변하고, 화면에 나온 노트북의 로그는 이 자료만으로 주행
상태를 정확히 읽기 어렵다. 영상은 동작을 살펴보는 참고자료이며 센서 거리, 실행된
충돌 판정, 무장 상태, 목표 도달 여부의 직접 증거가 아니다.

파일의 원 촬영 시각 메타데이터는 9월 14일 22:55:24이고, 앞서 사용자가 제공한 분석의
로그 구간은 22:56:28~22:57:05다. 시계 동기나 같은 구간이라는 근거 없이 두 기록을
초 단위로 맞추지 않았다. 새 영상에 과거의 11회 탈락·7회 정지 수치를 적용하지 않는다.

노트북과 센서에서 이어진 케이블 일부가 바닥에 끌리는 모습도 보인다. 주행 전 고정 상태를
점검할 항목이지만, 이번 정지·회전의 원인으로 확정하지 않는다.

## 다음 주행에서 원인을 구분하는 기록

- `all_candidates_rejected:*`: 모델 후보와 안전 검사 결과를 확인한다.
- `first_collision.kind`: `occupied`는 관측 장애물, `unknown`은 미관측 셀,
  `outside_map`은 맵 범위 밖이다. 경로의 첫 차단 샘플과 대표 차단 셀을 기록하며,
  이 하나가 모든 충돌 원인을 뜻하지는 않는다. `sample_index=0`이면 현재 위치부터
  로봇 크기 검사에 걸린 것이다.
- 전방 근접 정지: tracker의 전방 최소 거리·측정 방향을 확인한다.
- `path_exhausted`: 짧은 경로를 이미 소진해 새 경로를 기다리는 상태다.
- 센서 stale/추론 결과 만료: 원본 센서 stamp, 수신시각, 추론 시간과 결과 나이를 확인한다.
- 목표 도달 후 정지: `goal_reached_disarmed`로 다른 정지와 구별한다.
- 위치 추정: `/tf`, `/aft_mapped_to_init`, `/amcl_pose`, `/scan`을 함께 기록해
  정지 중 좌표 변화와 scan/저장 지도 어긋남을 확인한다.

확정된 계산 문제의 수정과 실제 주행에서 증상 감소를 확인하는 일은 구분한다.
연구실 적용은 [STABILITY_FIXES_KR.md](STABILITY_FIXES_KR.md), 검증 범위는
[STABILITY_VALIDATION_20260916.md](STABILITY_VALIDATION_20260916.md)를 따른다.

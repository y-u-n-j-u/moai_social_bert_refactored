# L자 복도 주행을 위한 진행량 판정과 지연 계측 보완

## 적용 시나리오와 범위

실제 시나리오는 **오른쪽 로봇 위치에서 출발 → 긴 복도를 왼쪽으로 직진 → 로봇 기준
좌회전 → 왼쪽 아래 목표에 도착**하는 L자 경로이다. 직진, 옆으로 피하는 경로,
코너 접근, 좌회전, 회전 후 진행을 회귀 테스트에 포함했다. 테스트의 좌표는 합성값이며
그림이나 RViz 영상에서 실제 복도 폭·길이를 측정한 값이 아니다.

U자·교차 경로는 경로 계산이 다른 구간으로 잘못 건너뛰지 않는지 확인하는 예외 테스트다.
실제 주행에 U자 경로를 추가하거나 모델 후보 개수를 늘리지 않는다.

기존 안정화 수정(저속 heading, 추종점, 안전한 후보 사이의 연속성 선택, 비동기 추론)은
유지한다. 이번 보완은 **bridge의 후보 진행량 검사**와 **계산 지연 계측**이다.
모델 구조·가중치·후보 수·GP 생성 방식은 변경하지 않았다.

## 1. 최종 목표 방향만 보던 진행량 판정 보완

기존에는 후보 끝점의 이동을 최종 목표 방향에 투영한 값이 0.10m 이상이어야 했다.
복도가 꺾이는 위치에서는 복도에 맞게 가도 이 값이 작을 수 있다.

합성 L자 경로 `(12,0) → (0,0) → (0,-3)`에서 로봇이 `(0.4,0)`에 있고,
후보가 코너 `(0,0)`까지 0.4m 가는 사례를 재현했다. 최종 목표 방향 진행량은 약
0.053m여서 기존 검사에서는 탈락한다. 새 검사는 복도 경로를 따른 0.4m 진행을 인정한다.
이것은 재현 가능한 판정 문제이며 **과거 반복 정지의 주원인으로 확정한 것은 아니다.**

기본 `candidate_progress_mode: route`는 추론 완료 후 최신 전역 경로를 현재 odom 좌표로
변환하고 다음을 검사한다.

1. 현재 위치와 후보를 같은 순서의 전역 경로 구간에 연결한다.
2. 경로를 따라 진행한 거리에서 경로로 복귀하는 데 늘어난 거리를 뺀다.
3. 인정하는 진행량은 현재 위치에서 후보 끝점까지의 실제 순변위를 넘지 않게 한다.
   코너에서 최근접 선분이 바뀌거나 제자리에서 왕복한 것을 큰 전진으로 세지 않는다.
4. 위 진행량이 기존 최소값 0.10m 이상인 후보를 남긴다.

기존 로봇 크기·지도 충돌, 점 사이 이동량, 보행자 거리 검사도 모두 통과해야 한다.
전역 경로에서 옆으로 멀어지기만 하는 후보가 자동으로 허용되는 것은 아니다.
따라서 보행자·장애물 회피 성능 전체를 개선했다고 보장하지 않는다.

`route_progress_max_distance: 1.50`은 전역 경로와 후보를 연결할 때 허용하는 최대 거리다.
**장애물 안전거리나 충돌 반경이 아니다.** 넓게 우회하여 이 범위를 벗어나는 후보는
거부될 수 있다. 이 기준은 실제 데이터와 함께 확인해야 한다.

전역 경로가 없거나 현재 위치에서 너무 멀고, 분기가 모호하거나 마지막 점이 현재 목표와
맞지 않으면 hold한다. 이전 경로를 무조건 실행하거나 최종 목표 직선 판정으로 조용히
대체하지 않는다. 비교 실험에서만 YAML의 `candidate_progress_mode`를 `final_goal`로
바꾸고 새 이미지로 빌드하면 기존 진행량 검사만 선택할 수 있다.

로그에서 `attempts[].goal_progress_m`는 비교를 위해 **기존 최종 목표 방향 값**을 유지한다.
새 판정은 `attempts[].route_progress`의 `effective_progress_m`, `arc_progress_m`,
시작·끝·최대 경로 이격 거리, `error`를 본다. 사용한 전역 경로는
`validation.progress_route`에 기록한다. `insufficient_route_progress`,
`route_deviation_exceeded`, `ambiguous_progress_route`, `progress_route_*` 사유를
기존 충돌 탈락과 구분한다.

## 2. RViz 지연과 경로 공백을 구분할 계측

`phase_timing_sec`에 지도 준비, GP 준비, 입력 준비·복사, worker 대기, 모델 호출,
결과 수집 대기, 최신 지도 검사, 전역 경로 연결 준비, 후보 검사·선택, 마커·경로 발행을
구분해 기록한다. 총 준비~판정 시간도 기록한다.

- 처리시간은 단조 시계로 측정한다. 모델 호출 시간은 CPU 전처리·GPU·출력 변환을
  포함하는 호출 전체이며 GPU 계산만의 시간이 아니다.
- `input_ages`는 dispatch/collection/validation 시점의 odom·scan·tracks 헤더 나이와
  수신 나이를 구분한다. 위치 이력의 최근 표본 나이도 기록한다.
- `previous_diagnostic_io_sec`는 **직전 로그 쓰기**의 직렬화·파일 쓰기 시간이다.
  현재 쓰기의 소요시간을 자기 기록 안에 넣을 수 없어 다음 기록에 남긴다.
- 전체 시간과 세부 시간은 겹치므로 모두 더하지 않는다. 발행 시간은 publish 함수
  실행시간이며 DDS 전달이나 실제 바퀴 반응시간이 아니다. 마지막 파일 쓰기는 다음
  기록이 없으면 집계할 수 없다.

기존 `summarize_stability_logs.py` 명령으로 각 단계의 평균·p50·p95·최대값과 표본 수를
요약한다. 예전 로그의 누락 필드는 0초로 만들지 않는다. 실패한 추론 사이의 모델 heading을
연속 예측으로 묶어 비교하지 않는다.

상위 위치 추정 노드가 오래된 자세에 현재 발행시각을 붙이면 헤더 나이만으로 실제 지연을
알 수 없다. 이번 수정은 FAST-LIVO의 시각 처리나 AMCL/TF 추정 자체를 고친 것이 아니다.
실제 지연은 원본 센서, TF, 차량 odometry, RViz와 실차 동시 영상을 함께 확인해야 한다.

## 연구실 적용과 확인

배포 브랜치는 기존과 같은 `jackal-stability-20260916`이다. 이전 커밋 `88f6123`에는
이 보완이 없다. clone한 최신 commit을 기록하고 [적용 안내](STABILITY_FIXES_KR.md)에 따라
overlay 이미지를 새로 빌드해야 한다. 터미널별 센서·모델 실행 명령은 유지한다.

첫 실차 비교는 빈 복도의 직진 → 코너 좌회전 → 도착 순서로 하고, 그다음 장애물과
보행자를 추가해 어느 조건에서 정지하는지 나눈다. 정지 사유, 발행 각속도 반전,
실제 차량 회전, 단계별 지연을 함께 본다. 사람이 접근했거나 경로가 위험해서 멈춘 것은
없애야 할 불필요한 정지로 세지 않는다.

충돌 검사 반경 0.50m, 전방 정지 0.75m, 보행자 거리, timeout, 속도 상한을 완화하지 않았다.
실차 정지 횟수와 요잉 감소는 아직 측정하지 않았다. 로컬 회귀 테스트의 결과와 범위는
[검증 기록](STABILITY_VALIDATION_20260916.md)에 정리한다.

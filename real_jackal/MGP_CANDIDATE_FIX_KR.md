# 안전한 원래 MGP 표본을 보존하는 수정

## 어떤 문제를 고쳤는가

기존에는 모델이 목표 표본 40개를 만들고 K-means로 대표점 20개를 만든 뒤 안전검사를 했다.
여러 점의 평균인 대표점이 벽이나 미관측 영역에 놓이면, 원래 표본 중 통과 가능한 점이
있었어도 후보 목록에서 사라질 수 있었다. 이 수정은 그 **압축 단계의 손실**을 보완한다.
과거 영상의 모든 빨간 후보가 이 원인 때문이었다고 확정한 것은 아니다.

새 기본값 `goal_candidate_policy: preserve_safe_samples`의 처리 순서는 다음과 같다.

1. 기존 모델·K-means를 그대로 한 번 실행한다. 중간 decoder 출력에서 원래 표본 40개도 읽는다.
2. 원래 표본과 대표점 각각에 기존 모델 지도 검사와 로봇 크기 검사를 적용한다.
3. **원래 안전했던 대표점은 그대로 보존한다.** 탈락한 대표점 자리만 안전한 원래 표본으로 보충한다.
4. 첫 보충점은 GP에 가장 가까운 점, 이후는 이미 확보한 안전점과 떨어진 점을 우선한다.
   동률이면 GP 거리와 원래 표본 번호로 결정한다. 1e-6m 이내의 같은 점을 복제해 채우지 않는다.
5. 보충 후 기존 모델의 목표 안전검사를 다시 통과해야 한다. 그다음 최대 5개 TGP 계산과
   bridge의 최신 지도·보행자·진행량 검사를 그대로 수행한다.

대표점은 계속 20개다. 안전한 표본이 부족하면 남는 자리를 위험한 원래 대표점으로 유지하고
계속 탈락시킨다. 안전한 점이 하나뿐이라고 여러 번 복제하여 안전 후보가 많은 것처럼 만들지 않는다.
원래 표본이 모두 위험하더라도 평균 대표점은 안전할 수 있으므로 그런 기존 대표점도 보존한다.

모델 구조·가중치·학습, 표본 40개·대표점 20개·TGP 상한 5개, GP 생성 방식은 바꾸지 않았다.
추가 샘플링이나 실패 후 무한 재시도는 없다. 기존 predictor와 군집화의 난수 소비를 유지하며
보충 선택은 난수를 사용하지 않는다. 다만 후보 좌표가 달라져 실제 주행이 달라지면 이후 센서
입력과 예측도 달라지므로 기존 주행 전체와 동일한 결과를 보장하는 뜻은 아니다.

## 안전 검사와 한계

충돌 반경 0.50m, 미관측 차단, 전방 정지 0.75m, 보행자 거리, timeout, 속도 상한을 유지한다.
안전한 원래 표본과 안전한 대표점이 모두 없으면 계속 hold한다. 초록 MGP는 끝점의 지도 검사
통과를 의미하므로 벽 너머의 안전한 끝점까지 가는 경로는 여전히 벽 충돌로 거부된다.

기존 **안전한 목표점 목록**은 보존하지만, 보충점이 GP에 더 가까우면 TGP 상위 5개 구성이
달라질 수 있다. 기존의 실행 가능한 경로가 항상 다시 생성된다는 보장은 아니다.
원래 표본 분포 자체가 복도와 맞지 않거나, 지도·TF·시각이 불안정한 문제는 별도로 남는다.

신경망 호출 횟수는 늘리지 않지만 원래 표본·대표점의 추가 지도/footprint 검사와 진단 기록은
CPU 시간이 든다. `worker_predict_sec`, `candidate_validation_sec`, 전체 처리시간과 결과 만료
횟수를 함께 비교해야 한다. 안전거리·timeout을 늘려 이 비용을 숨기지 않는다.

## 확인할 로그

bridge JSONL의 `model_input.goal_sampling`에 다음을 기록한다.

| 필드 | 의미 |
| --- | --- |
| `policy` | `preserve_safe_samples` 또는 비교용 `legacy` |
| `raw_count`, `raw_safe_count` | 원래 표본 개수와 안전한 표본 개수 |
| `original_count`, `original_safe_count` | 원래 대표점 개수와 안전한 대표점 개수 |
| `repaired_count`, `output_safe_count` | 보충한 자리 수와 보충 후 안전한 대표점 수 |
| `replacement_sources` | 대표점 `slot`에 넣은 원래 표본 `raw_index` |
| `raw`, `original` | 각 좌표, 모델 지도 셀·범위·안전 여부, footprint 안전 여부, 탈락 사유 |
| `output_points_local`, `output_safe_mask` | 최종 대표점과 재검사에 일치해야 하는 안전 여부 |

탈락 사유는 `occupied_model_map`, `unknown_model_map`, `outside_model_map`,
`footprint_occupied`, `footprint_unknown`, `footprint_outside_map`, `nonfinite` 등을 구분한다.
한 점에 여러 사유가 있을 수 있으므로 사유 개수를 합쳐 탈락한 점 개수로 읽지 않는다.

RViz MGP 마커는 실제 보충 후 대표점과 안전 여부를 표시한다. 마커 ID는 `100 + slot`이다.
비유한 점은 그리지 않아도 뒤의 점 번호를 압축하지 않는다. `selected_candidate_index`는
대표점 자리 번호이고 원래 표본 번호는 `replacement_sources`에서 따로 확인한다.

기존 `summarize_stability_logs.py` 명령은 이제 정책별로 보충 전후 안전 후보가 0개였던
예측 수, 0개에서 1개 이상으로 복구한 예측 수, 보충한 자리 수와 원인별 통계를 제공한다.
이 수치는 후보 단계의 결과이며 바퀴 정지 횟수나 실차 성공률이 아니다. 예전 로그에서
빠진 필드는 0으로 간주하지 않는다.

## 배포와 비교

같은 `jackal-stability-20260916` 브랜치의 최신 commit을 받아
[연구실 적용 안내](STABILITY_FIXES_KR.md)에 따라 새 overlay 이미지로 빌드한다.
기존 센서·모델 실행 명령은 유지한다. 이전 `6ecc8f3`에는 이번 보충 기능이 없다.
clone/pull만으로 이미 실행 중인 컨테이너가 바뀌지 않는다.

변경은 ROS 패키지 안에 포함되어 기존 overlay 빌드로 배포된다. 연구실 이미지의 원래
모델 소스와 checkpoint는 덮어쓰지 않는다. 모델 호출 중 해당 인스턴스에만 적용한
decoder 관찰 hook과 predictor 연결은 정상·예외 종료 모두 복원한다. 모델 API가 다르거나
기존 안전 재검사 결과가 예상과 다르면 조용히 우회하지 않고 오류/hold로 처리한다.

이미지 빌드의 실제 checkpoint smoke는 기본 설정, 원래 표본을 읽었는지, 안전 후보 개수와
보충 출처, hook·메서드 복원, 추론 전후 모델 parameter/buffer 해시 동일성을 확인한다.
개발 PC의 오프라인 테스트는 ROS·신경망 실행을 대체하므로 이 빌드 검사를 대신하지 않는다.

비교가 필요하면 YAML의 `goal_candidate_policy: legacy`로 별도 이미지를 빌드할 수 있다.
기존 저속 방향·추종·경로 안정화 변경은 유지하고 이번 MGP 보충만 끈다.
첫 실차 비교는 빈 L자 복도 직진·좌회전부터 하고 장애물·보행자를 단계적으로 추가한다.
안전 후보 복구율뿐 아니라 전체 유효 경로 비율, 정지 사유·시간, 조향 반전, 처리 지연을 함께 본다.

# 충돌 반경과 저속 방향 계산: 오프라인 민감도 분석

## 결론

- 실제 수집한 로컬 맵/고정 후보를 재검사했다. 0.50m → 0.45m 축소로 충돌 탈락 후보는
  22/145 → 21/145로만 감소했다. 이번 표본은 **5cm 여유 축소가 반복 정지의 주된 해결책**이라는
  가설을 지지하지 않는다. 0.40m에서는 11개로 줄지만 물리 안전성을 입증한 것이 아니다.
- 운영 코드를 그대로 호출해 0.9mm→1.1mm의 횡방향 위치 차이만으로 모델 입력 heading이
  0°→90°로 전환되는 사례를 재현했다. 반대 방향 잡음은 ±90°/180°를 만들 수 있다.
- 실제 수집 odom의 0.4초 재표본화에서도 유사한 민감도를 관찰했다. 다만 **실제 bridge의
  timer 이력/모델 theta를 기록한 것이 아니므로**, 특정 과거 예측 탈락이나 요잉의 원인으로
  확정하지 않는다. 모델 theta와 이력의 계측/고정 입력 비교가 다음 우선 작업이다.
- 안전거리, timeout, heading 함수, 모델, 추종 제어, 실행 중 컨테이너/이미지는 변경하지 않았다.

  서비스 호출, 노드/daemon 재시작 없이 임시 파일만 생성했다.

  맞는 맵이 **유일할 때만** 연결했다. 32회 연결, 5회는 맵 누락/모호성으로 제외했다.
- 원래 반경 0.50m로 충돌 수, 현재 위치 충돌 여부, 최초 충돌점을 원본 로그와 다시 비교했다.
  연결된 모든 후보에서 일치했다. 일치하지 않으면 도구는 민감도 결론에서 해당 예측을 제외한다.
- OccupancyGrid의 float32 해상도 대신 원래 collision context 해상도(0.1)를 재계산에 사용했다.
  미세 반올림이 cell/보간 경계에 영향을 주지 않도록 했으며 원래 unknown 차단 정책도 유지했다.

| 검사 반경 | 충돌 후보 | 기존 충돌 후보 중 충돌 검사만 통과하게 된 수 |
| --- | ---: | ---: |
| 0.34m | 5 | 17 |
| 0.40m | 11 | 11 |
| 0.45m | 21 | 1 |
| 0.50m (기존) | 22 | 0 |
| 0.55m | 40 | 0 |

0.34m는 설정상 추가 안전 여유가 없는 비교값이다. 실차 적용 권고가 아니다.

남아 있을 수 있다. 모델의 후보 생성/선별 과정 자체도 반경의 영향을 받으므로 이 표를
실제 파라미터 변경 후 전체 파이프라인 결과로 해석하면 안 된다.

## 방향 재현

`heading_from_history()`는 마지막 두 위치의 이동량이 0.001m를 **초과**하면 그 방향을 쓰고,
아니면 odom yaw를 사용한다. 함수를 변경하지 않고 호출했다. yaw=0 기준:

| 마지막 이동 벡터 | 선택 기준 | 계산 heading |
| --- | --- | ---: |
| (0, 0.0009)m | odom yaw | 0° |
| (0, 0.0011)m | 위치 차이 | +90° |
| (-0.0011, 0)m | 위치 차이 | 180° |
| (0, -0.0011)m | 위치 차이 | -90° |
| (0.04, 0)m | 위치 차이 | 0° |

수집한 odom을 수신시각 기준 0.4초 간격으로 재표본화한 **참고 계산**은 70쌍 중 25쌍에서
위치 차이를 선택했고, 계산 heading과 해당 odom yaw의 최대 차이는 약 175.57°였다.
비교 구간 prediction에 기록된 자세 범위는 x 약 1.86mm, y 약 2.06mm, yaw 약 0.105°였다.
하지만 bridge의 history timer 위상/수신 순서와 이 재표본화는 같지 않다. 실제 모델이
175.57°를 사용했다거나 실제 조향이 그 각도로 회전했다고 주장할 수 없다.

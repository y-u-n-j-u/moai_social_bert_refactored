## 수정 내용

1. **모델 기준 방향:** 기본 `motion_guarded`는 충분히 신뢰할 수 있는 이동에서는 학습과
   같은 마지막 이동 방향을 쓰고, 정지·저속 잡음에서는 odometry yaw를 사용한다. 기존 최근 2점/1mm
   함수는 비교용으로 보존하고 실제 사용 theta, 기존 계산 theta, 위치 이력과 표본시각을 기록한다.
   `adaptive` 모드는 실험용이며 기본으로 사용하지 않는다. 모델 가중치는 변경하지 않았다.
2. **추종점:** 최근접 꼭짓점으로 되돌아가던 계산을 경로 선분 투영과 전방 거리 계산으로 바꿨다.
   짧은 경로 끝점을 이미 지난 경우 뒤로 돌아서지 않고 `path_exhausted`로 새 경로를 기다린다.
3. **후보 선택:** 기존 지도/로봇 크기/사람/점 간 이동/전진량 검사를 통과한 현재 후보만
   현재 방향, 짧은 구간의 회전량, 이전 경로와의 차이, GP 거리로 비교한다. 이전 경로는
   점수 계산 참고이며 실행 fallback이 아니다. 모두 탈락하면 빈 경로와 hold를 발행한다.
4. **도착:** 목표 ID별 완료 상태를 공유한다. 목표와 경로는 단일 메시지로 전달하며,
   도착 후 좌표 추정이 변해도 새 goal 전까지 완료 상태를 유지한다. 목표 근처 감속을 추가했다.
5. **입력 보호:** 기존 수신 timeout을 유지하면서 센서/계획 원본 시각도 검사한다.
   비유한 자세·사람 좌표·속도, 비정상 스캔을 거부한다. 추론·검사가 끝난 뒤에도
   입력 신선도를 확인한다. NaN 후보는 JSON 기록 때문에 정지 처리가 누락되지 않는다.
6. **계측:** 요청/실제 발행 속도, 추종점, heading error, 정지 사유, 후보 점수,
   추론 시간과 센서 age를 기록한다. 로그 통계 도구를 함께 제공한다.
7. **배포:** 기존 연구실 이미지 위에 수정 패키지만 별도 workspace/image로 빌드한다.
   기존 환경 기록·백업, source/import/config 해시 확인, 적용·되돌리기 절차를 제공한다.
8. **추론과 센서 수신 분리:** 단일 worker가 복사한 지도와 입력으로 추론하는 동안 ROS
   콜백은 새 센서·목표·이력을 수신한다. 완료 후 최신 지도·위치·사람 정보로 다시 검사한다.
   바뀐 목표·좌표계 또는 1.20초를 넘은 결과는 폐기한다. 0.05초로 완료를 확인하고
   재계획 주기를 만족하면 같은 콜백에서 다음 추론을 시작해 불필요한 빈 시간을 줄인다.
9. **충돌 사유 계측:** 기존 맵 판정을 유지하며 첫 충돌이 점유·미관측·맵 바깥 중 무엇인지
   기록한다. tracker에는 전방 최소 거리와 측정 방향을 추가한다.
10. **보행자 구간 검사:** 예측점 사이의 상대운동 최소거리도 검사한다. 이것은 검사 누락을
    막는 안전 보완이며 정지 감소를 위한 변경은 아니다.
11. **L자 코너 진행량:** 최종 목표 직선 방향만 보던 후보 진행량을 최신 전역 경로 기준으로
    검사한다. 코너 투영 전환으로 실제 순변위보다 큰 진행량을 인정하지 않는다. 기존 진행량은
    로그에 별도로 남긴다. [추가 수정 설명](ROUTE_PROGRESS_FOLLOWUP_KR.md)을 참고한다.
12. **지연 분해:** 지도·GP·입력 준비, worker 대기·모델 호출, 결과 수집, 최신 경로 연결과
    후보 검사·선택, 발행 시간을 구분한다. 센서 헤더·수신·이력 나이와 직전 로그 I/O를 기록한다.

## 검증

ROS가 없는 Windows 개발 PC에서 최신 Python 회귀 테스트 **176개와 하위 사례 56개**를 통과했다.
기존 `88f6123`의 125개에서 L자 코너·경로 연결·지연 계측·요약 도구 검증을 추가한 결과다.
테스트는 센서·ROS 전송과 모델을 대체하는 test double을 사용한다. 실제 모델의 입력
좌표변환 함수, bridge·tracker 콜백과 제어 계산을 실행하지만 DDS·GPU·모터 시험은 아니다.

- 기존 충돌·보행자 검사, 지도 미관측 차단 유지
- 방향/각도 wrapping, 제자리 회전과 저속 방향, 모델 입력·출력 좌표변환 일관성
- 선분 추종, 코너·중복점·끝점, 목표 감속의 유한 시간 도달
- 안전하지 않은 후보 제외, 현재 후보가 없을 때 과거 경로를 실행하지 않음
- bridge → tracker 유효 계획 실행, 거절 시 정지, tracker → bridge 완료 공유
- 잘못된 데이터, 센서/계획 시각 지연, 미래 시각, E-stop·근접 정지 유지
- 가감속 제한 전 요청과 실제 발행 명령 구분
- 실제 Python worker 실행 중 센서 콜백 처리, 목표·frame 변경 및 좌표계 변경 후 원복 검사
- 1초 합성 추론의 연속 완료 시 경로 간격 1초 유지, 동시 모델 작업은 하나로 제한
- 기존 맵 판정과 1,200개 비교 입력의 결과 일치 및 계측의 맵 비변경
- 로그 디스크 쓰기 실패가 정지 명령을 막지 않음, 결과 미수집 기록의 정상 집계
- 실제 시나리오 방향의 직진·코너 접근·좌회전·회전 후 진행·작은 옆 우회 합성 사례
- 코너 근처 최소 순변위, 전역 경로 이격 제한, U자·교차 구간의 잘못된 연결 거부
- 추론 완료 후 최신 전역 경로 사용, 누락·비정상·목표 불일치·좌표 이동 시 hold
- 가상 시계로 단계별 지연 분리, 계측 실패의 제어 영향 차단, 미래 헤더와 누락 값 구별

## 실차에서 남은 검증

실제 주행 정지 횟수·시간·요잉이 감소했다고 아직 주장할 수 없다. 이번 heading 선택과
후보 점수는 기존 checkpoint로 실차 비교가 필요하다. FAST-LIVO의 빈 포인트와 AMCL/TF의
정지 중 변동도 여기서 해결한 항목이 아니다. 모든 후보가 실제로 위험하거나 데이터가
오래되면 정지는 유지한다. 새 원본 시각 검사가 거부한다면 로그의 stamp/처리 지연을 확인한다.
worker 분리 후에도 main 콜백의 지도 생성·후보 검사 시간은 실차 측정이 필요하다.
모델 자체가 멈추면 작업을 무제한 추가하지 않고 정지 상태를 유지한다.

충돌 반경 0.50m, 미관측 차단, 속도·각속도 상한, 센서·경로 timeout을 완화하지 않았다.
실제 바퀴 동작은 RViz/명령 로그만으로 판단하지 말고 차량 odometry와 영상도 함께 비교한다.
연구실 적용은 [STABILITY_FIXES_KR.md](STABILITY_FIXES_KR.md)를 따른다.

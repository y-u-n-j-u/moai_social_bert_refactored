# 모델 후보 선택과 실제 추종 검증

발표에서는 **후보 생성**, **시스템의 후보 선택**, **추종기에 발행한 경로**, **실제 주행**을 각각 보여준다. 모델은 미래 로봇 경로 후보를 생성한다. 최종 선택 점수는 학습된 신뢰도가 아니라 브릿지의 규칙이다. 경로 모양이 신경망 내부에서 왜 만들어졌는지까지 이 점수로 설명할 수는 없다.

## RViz에서 볼 항목

`field_scripts/real_jackal_ped_map.rviz`에 후보/선택 표시와 추종 목표를 추가했다.

| 표시 | 의미 |
| --- | --- |
| 빨간 후보 | 지도·몸체 충돌, 진행량, 보행자 거리 등 검사에서 탈락. 경로점이 없는 후보는 별도 창에 표시 |
| 파란 후보 | 검사에 통과한 다른 후보. 경로 끝에 후보 번호 표시 |
| (주황 후보 없음) | 11-08에 시작 방향 기준(`selection_heading_limit_rad`)에서 제외된 후보도 **빨간색**으로 바꿨다. 탈락(검사 실패)과 방향 제외는 색으로 구분되지 않는다(`score.eligible`/로그로만 구분) |
| 초록 후보 | 선택되어 **추종기에 발행된 새 모델 경로**(굵은 선 0.075) |
| 굵은 초록 후보 / 굵은 초록 선(0.085) | 모델 후보가 선택된 뒤 **교체된 경우**(후보 선, 0.075) / 실제 발행된 유지·대체·복구 경로(선, 0.085). 11-08에 노랑·주황에서 초록으로 바꿨다. **모델 경로와 교체 경로는 색이 아니라 굵기(0.075 대 0.085)와 `published_nonmodel_path` 네임스페이스로만 구분된다** |
| 흰 선 | 추종기로 발행된 Path |
| 주황 점 / TRACKER 문구 | 현재 추종 목표점 / 경로·틈·보조 조향 또는 정지와 발행 속도 |

사람은 현재 트랙 점으로 표시한다. 사람 잔상은 기본 OFF이며 `show_trails:=true`로 켜도 최대 5초만 보관한다. 사라진 ID 또는 오래된 트랙의 표시는 제거한다. 모델의 보행자 이력에는 영향을 주지 않는다.

로봇이 지나온 오도메트리 궤적은 기본 화면에서 숨긴다. 주행 기록과 대조할 때는 RViz의 `Robot trail (travelled path)`를 켜서 확인할 수 있다.

## 후보 점수와 이유를 보여주는 별도 창

기존 터미널 런처의 일반 주행 4번 RViz 또는 보행자 인식 모드 3번 RViz를 실행하면 후보 평가 창도 함께 열린다. 런처가 최신 `selection_view.py`를 컨테이너로 복사하고, RViz와 같은 ROS·화면 환경에서 시작한다. 같은 사용자와 ROS domain에서는 창 하나만 유지하며 RViz 내부 재시작 동안에도 유지한다. 창을 직접 닫거나 `stop_all.bash` / `kill_all.sh`로 종료할 수 있다. 시작 오류는 해당 실행 폴더의 `selection_view.log`에서 확인한다.

RViz를 실행하는 PC에서 같은 ROS 환경과 DDS 설정을 적용하고 다음 명령으로 연다. 그래픽 화면과 Python Tk가 필요하다.

```bash
python3 real_jackal/field_scripts/selection_view.py
```

RViz 경로 끝의 `C번호`가 표의 후보 번호와 일치한다. 창은 `/spu_bert/selection_evidence`를 구독해 점수 합계·항목, 탈락 이유, 모델 후보 선택, 추종기에 발행한 경로를 보여준다. 대체·유지·복구·정지는 별도 상태로 표시한다. 발행 기록은 실제 주행 궤적과 대조해 추종 여부를 확인한다. 이전 bridge나 bag에 이 토픽이 없으면 수신 대기로 표시된다.

## 왜 이 후보인가

1. Nav2 경로에서 GP를 고른다. SPU-BERT의 MGP가 목표를 샘플링하고, 군집화와 지도 검사 후 GP 거리로 목표 순서를 매긴다. TGP가 그 목표들에 대해 로봇 경로를 만든다.
2. 후보 경로를 지도·몸체 충돌, 이동량, 목표 진행량, 보행자 거리 기준으로 검사한다.
3. 통과한 후보의 **입력 순서 비용 + 이전 경로와의 거리 비용 + 시작 방향 비용 + 장애물 여유 비용**을 비교한다. 비용은 낮을수록 우선한다. 입력 순서는 탈락 후의 선택기 입력 순서이며, 모델 확률이 아니다. 이전 경로 옵션이 있으면 이 옵션도 함께 비교한다. 동점이면 앞선 입력을 쓴다.
4. `selection_evidence`에는 후보별 실제 좌표, GP 거리, 검사 결과, 비용 항목·합계, 선택 이유, 선택된 후보 번호와 발행한 경로의 출처가 남는다. 선택 결과를 대체 경로로 바꾼 경우 둘을 구분한다.

학습 모델 밖의 규칙은 **GP 거리 탐색·안정화, MGP 군집화·거리 정렬, 지도와 보행자 검사, 후보 비용, 경로 유지·원호/Nav2 대체·복구, 추종기의 틈/회피 조향, 속도 제한·정지**다. 사람 점유 영역을 지우는 규칙과 사람 주변 스캔 마스크도 여기에 포함된다.

## 대체 경로와 보조 조향을 끈 비교

`model_evidence_only:=true`를 브릿지와 추종기에 함께 적용한다. 새 모델 후보만 발행하며, 대체 경로·이전 경로 유지·복구·우회 GP 보조·틈/보조 조향은 끈다. Nav2 기반 GP, 후보 검사·점수, 경로 추종과 감속은 남는다. 유효한 모델 후보가 없으면 멈춘다.

비교 모드에서는 사람 주변 점유와 스캔을 지우지 않는다. 기존 시험 YAML이 0으로 둔 보행자 거리 검사·정지를 각각 최소 1.20m/0.90m로 복원한다(중심 거리). 원본 스캔 근접 정지, 센서/경로 감시, 물리 비상정지와 속도 제한을 유지한다. 스캔 최소거리 0.35m보다 작은 물체를 소프트웨어가 볼 수 있다는 의미는 아니다.

갱신한 ROS 패키지를 빌드해 사용한다. 구형 이미지에 YAML만 복사하면 새 launch 인자와 노드 코드가 반영되지 않는다. 기존 브릿지/추종기와 중복해서 띄우지 않는다. 먼저 로봇이 연결되지 않은 환경에서 기록을 재생하거나 dry-run으로 후보와 명령을 확인한다.

```bash
ros2 launch moai_jackal_spubert real_jackal_spubert.launch.py \
  model_evidence_only:=true cmd_vel_topic:=/spu_bert/cmd_vel_dryrun \
  config_file:=/path/to/real_jackal_social005.yaml
rviz2 -d /path/to/repo/real_jackal/field_scripts/real_jackal_ped_map.rviz
```

실제 속도 토픽을 쓰는 비교 모드는 매핑한 `deadman_joy_topic`과 `deadman_button`이 없으면 RUN을 거부한다. 버튼을 누르는 동안만 허용하고, 버튼 해제나 신호 만료 시 자율 명령을 0으로 내고 RUN을 해제한다. 다시 눌러도 자동 재출발하지 않는다. 장비마다 ROS Joy 토픽·버튼·자동 반복 주기와 mux 우선순위가 다르다. 사람이 없는 곳에서 자율 채널과 하류 명령을 함께 보며 **해제, 끊김, 재연결, 명시적 RUN**을 확인해야 한다. 이 기능은 자율 추종기의 정지이며, 다른 teleop 발행자의 모터 명령까지 강제 정지하는 기능은 아니다.

## 제출할 증거

1. 새 bag에 `selection_evidence`, `predicted_path`, `tracker_diagnostics`, odom, 상류 `cmd_vel`, 로봇측 mux 하류 명령을 기록한다. `start_bag3.bash`에 추가했다. 실제 Joy/수동 명령 토픽을 확인했다면 기록기 환경에 `EVIDENCE_JOY_TOPIC`, `EVIDENCE_MANUAL_CMD_TOPIC`도 지정한다.
2. `verify_jackal_link.bash` 등 읽기 전용 점검으로 실제 mux 하류 토픽과 발행자/구독자를 확인한다. 코드 커밋과 실험 모드, 가중치 해시, 적용 설정(브릿지/추종기 parameter dump), 영상과 조작 여부도 함께 남긴다. 기존 녹화 bag에 새 증거 토픽이 없으면 추측으로 채우지 않는다.
3. 종료된 bag에서 보고서를 만든다. ROS 환경이 없는 PC에서는 `--export-events`로 내보낸 JSONL을 다시 분석할 수 있다. `--plot`은 Matplotlib가 필요하다.

```bash
python3 real_jackal/field_scripts/analysis/model_following_evidence.py /path/to/closed_bag \
  --out /path/to/new_report --export-events --plot
```

수동 명령 토픽도 녹화했다면 `--manual-cmd-topic <확인한 토픽>`을 지정한다. 보고서는 Path 타임스탬프·좌표계와 후보 기하를 일치시킨 뒤, 추종기·상류·하류 명령과 odom을 대조한다. 대체/유지/보조 조향, 명령 불일치, 누락은 따로 집계한다. `report.html`에서 후보별 점수와 이유를 펼쳐 볼 수 있고, `summary.json`과 `samples.csv`를 첨부할 수 있다. **명령 일치 표본 비율은 주행 시간 비율이 아니다.** 모델 경로를 실제로 따라간 근거로 사용하려면 같은 경로에서 odom 진행량과 횡방향 오차를 함께 보여주고, 수동 개입 여부를 별도로 확인한다.

## 미관측 셀과 기둥 옆 보행자

- 정적 지도, 실시간 라이다 격자, 사람 트랙은 서로 다르다. 라이다 점만 보면 기둥과 사람은 둘 다 점유다. YOLO·LiDAR로 추적된 사람은 모델에 별도 입력된다. 정적 지도에 등록된 기둥은 사람 점유 지우기로 지워지지 않지만, 실시간 로컬 맵의 작은 기둥 셀은 사람 근처에 있다는 이유로 함께 지워질 수 있다.
- 기존 규칙은 사람 중심 0.5m 안에서 시작해 연결된 점유 셀을 찾고 총 60셀 이하이면 지운다. 큰 벽 덩어리는 남고, 사람이 기둥에 닿지 않아도 두 물체가 제거 범위에 들면 함께 지워질 수 있다. 벽·기둥에서 떨어진 사람을 쓰는 것은 시험 조건으로 명시하고 이격 거리를 기록한다.
- 미관측은 통과 가능한 곳으로 **가정**할 수 있지만, 기둥 뒤나 사람에 가려 센서가 못 본 곳도 허용된다. 로컬 충돌 정책 변경, 모델 지도 입력의 unknown→free 변환, Nav2의 unknown 허용은 서로 다른 비교다.

```bash
python3 -B real_jackal/scripts/analyze_offline_sensitivity.py --compare-unknown \
  --capture real_jackal/analysis/2026-09-15-sensitivity/capture.json.gz --radii 0.50
```

9월 15일 캡처에 이 비교를 적용한 결과: 지도 일치 32회, 검사 가능한 후보 145개, 충돌 22개 → 22개. 이 표본에는 미관측만으로 탈락했다가 살아나는 후보가 없었다. 후보·지도·몸체 반경을 고정한 충돌 검사 비교이며, 11월 보행자 주행이나 모델 재추론 결과는 아니다.

## 2. 매뉴얼: 실시간 주행 시작과 순서

### 시작
1. (부팅 후) `xhost +SI:localuser:root`
2. `cd ~/capstone_navi/real_jackal/field_scripts && ./open_jackal_terminals.bash --live`
3. 터미널 창이 8칸으로 열린다. **1번 칸에 sudo 비밀번호를 한 번 입력**한다(네트워크 설정). 이후 설정 칸이 자동으로 이어진다(약 1~2분).

### 칸별 역할
| 칸 | 이름 | 하는 일 | 실행 |
|---|---|---|---|
| 1 | HOST | 네트워크 설정(sudo) + 컨테이너 시작(이미 켜져 있으면 건너뜀). 끝나면 `container.ok` | 자동 |
| 2 | SENSORS + PEOPLE + NAV2 | 라이다, LIO, 카메라 + YOLO + 사람 추적, 스캔, Nav2, 로봇 위치 표시. 스캔/LIO/사람 추적이 나오면 "stack ready"(`stack.ok`) | 자동 (1번 후) |
| 3 | RVIZ (map only) | 지도만 있는 RViz | 자동 (2번 후) |
| 4 | BRIDGE | **저장소의 브릿지 코드와 설정을 컨테이너에 복사한 뒤** 브릿지 + 추종기 시작. 움직임은 꺼진 상태 | 자동 (2번 후) |
| 6 | STATUS | 부하, 프로세스, 브릿지 상태(읽기 전용) | 자동 |
| 7 | CHECK | 주행 전 점검(AMCL 표준편차, 로봇 연결, 센서 속도) | **직접 Enter** |
| 8 | RUN | **주행 시작(로봇이 움직임)**. 컨트롤러를 잡은 분이 준비된 뒤에만 | **직접 Enter** |
| 9 | AFTER THE RUN | 녹화(rosbag)를 안전하게 닫음 | **직접 Enter** |

- 앞 칸이 실패하면 뒤 칸은 "waiting for: …"로 계속 기다린다. 실패한 칸을 고치고 그 칸만 다시 실행한다(흐름은 `/tmp/jackal_tabs.*/*.ok` 파일).
- 일반 모드(`--live` 없이)는 예전 10칸이고 STOP 칸이 있다. `--ped`는 보행자 인식 시험.

### 주행 순서
1. 1~4번이 끝날 때까지 기다린다.
2. RViz에서 빨간 `2D Pose Estimate`로 위치를 찍고 **방향까지 끌기**.
3. 초록 `2D Goal Pose`로 목표(**브릿지가 켜진 뒤에**. 브릿지를 다시 켜면 목표가 지워짐).
4. 7번 CHECK(Enter): AMCL x≤0.60, y≤0.20, yaw≤10° 확인.
5. 컨트롤러 준비 → 8번 RUN(Enter) 또는 대화에서 "run"(한 번만).
6. 주행 후 9번 AFTER(Enter), 분석은 `field_scripts/analysis/`(11-09 일지, `drive_an_v5.py` 자율 구간 분석 등).

### 정지
- **컨트롤러의 비상정지가 기본 정지 수단**이다.
- 컴퓨터에서: `ros2 service call /spu_bert/enable_motion std_srvs/srv/SetBool "{data: false}"`(컨테이너 안). 컴퓨터/네트워크가 멈추면 동작하지 않는다.
- 정지 조건(장애물/사람)은 11-02, 11-09 결정으로 꺼져 있다. `never_hold`가 켜져 있으면 계획 실패 시 마지막 계획 경로를 최대 6초 따라간다(그동안 후보 재검사 없음).

## 3. RViz 화면 읽는 법

| 표시 | 의미 |
|---|---|
| 하늘색 작은 점 | **로봇의 현재 위치** |
| **연두색 굵은 선(1줄) + `C번호` 라벨** | **로봇이 실제로 따라가는 경로**(모델 후보가 그대로 발행되든, 이전 경로가 이기든, fallback이든). **매 주기(약 1초) 갱신** |
| 파란 얇은 선 + `C번호` + 끝의 파란 공 | 검사를 통과한 후보와 자기 목표 샘플(MGP) |
| 빨간 얇은 선 + 끝의 빨간 공 | 검사에서 탈락한 후보(최대 2개만 표시) |
| 주황 작은 공(연두 선 위를 따라 움직임) | **추종 목표점**(추종기의 lookahead, 로봇 앞 약 0.7m). 움직임이 꺼지면 사라짐 |
| 자홍색 점 | 추적된 사람 |
| 지도의 분홍/자홍 작은 점 | 라이다 스캔 점 |

### 왜 두 가지(연두 선과 후보 선)의 갱신 주기가 다른가
- 후보(파랑/빨강 선과 공)는 **로봇이 목표 샘플에 도달할 때까지 고정**한다(1초마다 바뀌면 너무 빨라서, 11-09 요청, 최대 20초, 약 12초마다 교체).
- 연두는 "실제로 가는 경로"여야 하므로 **매 주기** 바뀐다(약 2.5초마다 바뀜). 그래서 연두가 고정된 후보 사이에서 혼자 움직이는 것처럼 보인다. 사용자가 "지금처럼" 두기로 결정(11-16). 대안: 전부 매 주기 갱신(가장 정확, 화면이 1초마다 바뀜) / 전부 고정.
- **경로가 6줄 나오는 이유:** 후보 5줄 + 연두 1줄. 연두가 후보와 겹치면(모델 후보가 그대로 발행) 5줄로 보이고, 이전 경로/fallback이 이기거나 후보가 고정된 동안 연두만 바뀌면 6줄. 후보 2 + 대체 후보 4 + 연두 1로 7줄도 가능.

### 경로가 만들어지는 과정(코드로 확인)
최종 목표는 하나(`2D Goal Pose`) → Nav2가 루트를 만듦 → 루트 위 앞쪽(최대 8m)에 유도점 → 그 근처에 목표 샘플(MGP) 40개(`d_sample 40`) → 몸체가 지도에서 안전하게 들어갈 수 없는 샘플 제외 → 모델이 최대 5개(`tgp_top_k 5`) 고르고 샘플마다 경로 1줄(후보) → 후보 5개와 **이전 경로**를 점수로 비교해 하나 발행. 후보 경로 끝은 자기 목표 샘플 근처(측정 중앙값 0.11m).
- 모델 내부의 5개 고르는 기준(순위 방식)은 코드를 끝까지 읽지 않았다.

### "이전 경로가 이겼다"의 뜻
후보와 이전 경로를 같은 점수(총비용, 낮을수록 좋음)로 비교해서 이전 경로의 점수가 가장 낮은 것. 이전 경로는 자기 자신과 같아서 "이전 경로와의 거리"(연속성) 항목이 0이라 자주 이긴다(11-09 주행에서 약 40%). 조건: 2초 이내에 만든 것, 로봇이 경로에서 0.35m 이내, 지금 다시 검사 통과.

## 4. 후보 결정 창(`Jackal Candidate Decisions`) 읽는 법
- 위 문구는 `모델 선택`만.
- 표 최대 5행. **맨 위 `선택·발행` 행 = 지금 로봇이 따라가는 경로(RViz의 연두 선과 같은 `C번호`)**. 이전/복구 경로이면 번호는 그 주기에 다른 후보가 안 쓰는 번호이고 판단 이유가 `이전 경로 유지` 등이다.
- 나머지 행은 `검사 통과`/`검사 탈락`(탈락은 최대 2개). 판단 이유: 탈락은 실제 이유, 통과는 `이전 경로가 선택됨`/`대체 경로가 선택됨`/`선택 경로보다 총비용이 높음` 등. fallback 후보도 `C번호`(번호는 한 주기에서 겹치지 않음).
- 후보 행은 RViz와 같은 묶음(브릿지가 정한 `display_set`)이고, `선택·발행` 행만 매 주기 갱신된다. RViz는 후보 5줄 + 연두 1줄을 그리지만 창은 `선택·발행`을 합쳐 5행이라 이전 경로 발행 시 후보 하나가 창에서 빠질 수 있다.
- **총비용** = 입력 순서(0.15×순서) + 연속성(3.0×이전 경로와의 거리) + 시작 방향(0.3×rad, 34° 넘으면 제외) + 장애물 여유(소프트 마진, 가중 1.5). 낮을수록 좋음.

## 7. 알아 둘 점
- **팀원(junwoo)에게 알릴 것:** `mgp_fallback`/`never_hold`/표시 변경 모두 시험 설정 파일에서 켜져 있음, 색 규칙(연두 = 실제 경로, 파랑 = 통과 후보, 빨강 = 탈락, 흰색 없음), RViz가 지도만 나오는 설정으로 바뀜, 후보 결정 창의 `선택·발행` 행.
- `never_hold` 동안은 후보 재검사 없음(최대 6초, 약 1.5m).
- 이날 부하(load average)가 19까지 올랐다(RViz, 터미널 창 등). 11-09 주행의 `odom_missing_or_stale` 원인과 관련 있을 수 있으나 확인 안 함.
- 이 날 대화에서 영어/일본어가 섞여 나왔고 사용자가 여러 번 "한국어로 말하라"고 했다. **사용자에게는 한국어로만 답한다.**

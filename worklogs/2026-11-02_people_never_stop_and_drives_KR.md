# 2026-11-02 사람이 로봇을 멈추게 하지 않는 설정, 주행 3회, 정지 원인 분석, 화면 정리

코드는 `capstone_navi` 브랜치 `jackal-real-drive-fixes-20260912`의 `c272fbe`(사람 거부/정지/감속 끔) ~ `7fd6a53`까지 푸시했다. 오프라인 테스트 224개 통과.
**이미지 `drive-1025`에는 사람 제외 반경 0.8, 감시 스크립트 변경, RViz 배치, 오버레이 변경이 없다**(컨테이너에만 적용, 저장소에는 있음).
런처 3번 칸이 설정과 `start_nav2_bridge.bash`를 저장소에서 복사하므로 다시 올리면 적용된다. 이미지를 새로 만들려면 `drive-1026`.

## 1. 요약

- **사용자 결정:** 사람은 로봇을 멈추게 하지 않는다. `minimum_human_center_distance` 0, `human_stop_distance` 0, `human_slow_distance` 0, `human_scan_mask_hard_stop` true(0.30m 즉시 정지에서도 추적된 사람 제외), 감시 스크립트의 `obstacle_too_close < 0.26m` 정지 제거. e-stop만 남는다.
- **정정:** 10-23의 "거부 반경 0.5"는 실제로 적용되지 않았다. 후보 거부 거리는 `max(설정, 몸체0.44 + 사람0.35 + 마진0.20)` ≈ 0.99m. 0일 때만 꺼지도록 코드를 바꿨다.
- **추적에 잡힌 사람만 규칙에서 빠진다.** 추적이 놓친 사람(바싹 붙을 때 추적 점수가 떨어지고 중심이 어긋남)은 스캔 장애물로 남아 정지를 일으켰다. 제외 반경 0.5 → **0.8m**.
- 주행 3회(11-02): 모두 사람 때문에 멈춘 것은 아니었다. 정지의 주원인은 **지도 기반 몸체 충돌 검사**.

## 3. 정지 원인 (3차 롤링 맵 분석)

- 몸체 반경 0.44m(로봇 0.34 + 마진 0.10) 안에 **점유나 모름 셀이 있으면 후보/유도점 탈락**. 정지 지점에서 물체는 0.34~0.44m 사이(몸에 닿지는 않았지만 마진 침범)였다.
- 22~47초(25초): odom (5.0, -0.4)에서 앞 0.33m 물체, 좌우 폭 0.91m, 움직일 수 있는 방향 없음. 지난 주행에서도 같은 위치(x≈4.5~5)에서 멈췄다 → 고정 물체로 추정(미확인).
- 102.9초: 오른쪽 0.36m 물체가 1.4초 뒤 사라지고 그 자리에 사람 추적이 나타남 → **추적 안 된 사람이 스친 것**.
- 브릿지 판단: `rotation_circle 막힘` 15, `robot_footprint_collision` fallback 12, `adaptive_guidance_failed` 6, `odom_missing_or_stale` 4(기록상 오도메트리/스캔은 0.35초 이상 끊기지 않음).
- RViz 켠/끈 주행의 `odom_stale` 발생률은 같다(0.027/초) → RViz가 원인이 아니다. RViz는 CPU 5코어(load 11~14 vs 4)지만 LIO/브릿지 CPU는 그대로.

## 5. 알아 둘 것

- 컨테이너 안 스크립트는 `docker cp` 후 `bash --noprofile --norc /root/x.sh`로 실행(`pkill -f`/`awk /패턴/`은 자기 자신을 종료시킴).
- 브릿지를 다시 올리면 목표가 지워진다. `/spu_bert/final_goal_odom`을 map으로 바꿔 `/goal_pose`로 다시 넣을 수 있다(`last_goal.json`).
- Tk 창의 한글: 컨테이너에 한글 글꼴이 없어 호스트의 Noto Sans CJK를 복사했다(이미지에는 없음).
- 감시 알림은 이유가 같으면 0.5초마다 반복되어 폭주했다 → HUD가 이유 변경 때만 기록하도록 고침.
- `jackal-backup-*` 폴더(capstone_navi 아래)는 내 것이 아니라 커밋하지 않았다.
